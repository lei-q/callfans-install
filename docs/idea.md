一、背景
A 库：生产基准 MySQL，位于客户环境，包含全量业务数据。客户端不直接连接 A 库。

B 库：客户 MySQL，通常落后于 A 库。B 库只关注表结构和部分配置性质表的数据，不进行全量业务数据更新。

云库：云端 MySQL，作为中间标准库。云库只包含表结构和配置表数据，不包含其他业务数据。A 库的变更由管理员手动同步到云库。

客户端程序：已安装自研的 Python 更新程序。目标是增强该程序，使其定期将云库（期望状态）与 B 库（当前状态）进行比对，找出差异并安全地更新 B 库。

二、目标
以云库为源、B 库为目标，比对表结构差异和配置表数据差异。

只处理配置表清单中的表，忽略其他业务表。

生成可审查、可执行、尽量可回滚的迁移 SQL。

支持 dry-run、备份、日志、审计、错误处理。

集成到现有 Python 更新程序，提供 CLI 或可调用模块。

请在计划中调研并选择，给出理由、许可证、维护状态、Python 版本兼容性和风险：

数据库连接：PyMySQL、mysql-connector-python、SQLAlchemy

Schema 比对：migra / jsleekr-migra、sqlalchemy-diff、schema-sync、SQLAlchemy inspection、自研 INFORMATION_SCHEMA 比对

数据比对：tablediff-cli、自研基于主键/唯一键的分块比对

如果候选库不满足需求，说明自研方案的设计。

四、关键约束
客户端只连接云库和 B 库，不连接 A 库。

云库使用只读账号；B 库使用最小权限账号。

配置表必须有主键或唯一索引，否则计划中要说明如何处理（报错、跳过、人工确认）。

配置表清单应可配置，例如 YAML/JSON，支持忽略表、字段、索引。

结构差异范围需在计划中明确定义，包括但不限于：列、类型、长度、默认值、NULL、注释、主键、唯一索引、普通索引、外键、表选项（引擎/字符集/排序规则）等。

数据差异包括：新增行、删除行、更新行，生成 INSERT/UPDATE/DELETE。

MySQL DDL 隐式提交，事务策略需特别设计；回滚脚本需覆盖 DDL 和 DML。

执行前必须 dry-run 输出 SQL 和影响评估；执行时记录日志；失败可恢复。

传输使用 TLS，敏感信息不落盘明文。

更新应尽量幂等，并记录已应用的云库版本或校验和，避免重复执行。
